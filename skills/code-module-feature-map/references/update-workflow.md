# 双文档增量更新流程

适用于模块整理更新，及已有双文档模块在获授权的功能修改后的文档同步。AI 上下文是后续 AI 唯一的模块文档输入；开发者说明是供人快速了解模块的同步输出。沿用已配置路径，不自动改名或创建平行副本。

## 输入与基线

- 读取当前用户需求、项目规范、AI 上下文和有关源码，不要求读取开发者说明。AI 文档需保存两份输出路径、稳定 ID、业务事实、代码依据、覆盖范围及重要人工约定。
- 从 AI 上下文取得代码基线和覆盖边界，只读比较到当前 HEAD，同时检查暂存、未暂存及相关未跟踪文件；不要切换分支、重置或清理用户改动。
- 基线不可解析或旧文档缺少事实时，从源码和当前用户说明重新核对并补齐 AI 上下文，不通过回读开发者说明形成依赖，也不能声称完成精确增量核验。
- 从变更扩展到受影响页面和共享依赖。公共 Map、列组件需检查不同实参的调用方；权限、请求封装、实体及金额计算变化需考虑相关功能。
- 动态授权、字典、菜单及开关不一定反映在 Git 中；来源不可得时就地注明，不声称配置未变。

## 完成功能修改后的同步

1. 核对实际实现及影响范围，区分已完成变更、未实施建议和仍有缺口的部分。文档维护规则不授权额外代码开发或业务操作。
2. **先更新 AI 上下文**：维护业务事实、字段与 Map、按钮规则、报表、代码地图、修改影响、需求状态及后续验证方向。新增、拆分或移除功能时维护稳定 ID 和本文件内的全部关联引用；人工约定和保留内容存于本文件。
3. **再同步开发者说明**：依据已更新的 AI 上下文和实际代码生成对应业务流程、功能表、字段/Map、按钮、报表和相关建议，不以读取旧开发者说明为前提。信息不足时先从源码补全 AI 文档，再更新面向人的内容，不能只写一份而宣称同步完成。
4. 两份输出使用一致的模块 ID、本次分析批次和真实代码基线，标明覆盖范围；未复核部分不升级为全量已完成。完成一次获授权的功能更新后即进行此次同步，无须等到另一次“重新生成文档”的请求；仅讨论方案时不把候选行为写成已实现。

## 同步内容规则

- 功能变化：开发者流程图使用字母及数字后缀分支，功能表关联对应图/节点并列出操作端；稳定功能 ID 不因布局调整而重排。AI 文档保留同一功能的完整规则与代码依据，不依赖开发者流程图才能理解。
- 字段或 Map 变化：核对请求/响应、模型、校验、默认值与页面展示，记录未知和前后端差异；两份文档按各自读者需要表达同一事实。
- 按钮变化：说明用途、可用条件、不可用表现及关联功能；检查父容器、共享组件和后端派生标志。开发者主表不要求完整 URL/参数，接手所需接口细节在 AI 文档独立保存。
- 报表变化：开发者说明固定用“报表名称、报表链接、简述”三列；AI 文档另保留真实代码入口、筛选范围和影响修改的口径限制。普通列表和通用导出不冒充统计报表。
- 优化建议是否实施以当前代码为准；保留 AI 文档中的人工不采纳理由，不把历史候选建议当新任务。
- 不输出独立验证报告、集中待确认表或维护流水；必要缺口放对应条目，基线放元数据。

## 内部自检与交付

- 检查 AI 上下文内引用的 ID、代码路径和证据可解析；不提供开发者说明时，仍可定位实现、理解规则并判断修改影响，且能取得重建开发者说明所需的事实。
- 检查两份输出的业务事实、代码基线和覆盖范围一致；开发者流程图与表格按“图标识 / 字母节点”对应，名称、前置条件、状态结果和操作端有证据。
- 检查需要同步的内容已同时写入两份文档；保留稳定 ID 和 AI 文档中的人工约定。未执行的用例不能写成通过。
- 交付说明两份文档位置和同步范围。持续维护在当前调用或获授权的功能更新中执行，不创建后台监听或定时任务。
