# 需求处理与增量维护

更新模块说明或使用AI上下文处理新需求时读取。AI上下文是唯一模块文档输入，开发者说明是同步输出；本约定不额外授权业务开发。

## 核对当前输入

- 读取当前需求、项目规范、AI上下文及相关源码，取得基线、已有覆盖、稳定ID、人工决定、输出及索引位置；不回读旧人版补事实。
- 核实目标代码根目录source_root和本次整理对象。首次/重新生成使用相对于source_root的 `docs/code-module-feature-map/<项目>/`，在该目录生成 `developer-guide.md`、`ai-context.md`，命名和迁移细则见双文档结构；当次明确路径优先，普通增量维护沿登记位置。不要用skill仓库、会话目录或旧预览目录代替默认目标。
- 比较当前HEAD、暂存/未暂存/相关新文件；提交号不能覆盖工作区改动，不切分支、重置或清理用户文件。基线不可解析时从代码和当前说明补齐，注明非精确增量核验。
- 沿实际影响扩展到调用方、共享组件及依赖，检查不同入口/实参、字段、状态、权限、统计及导出的必要联动；实际角色、字典或部署未知不猜。

## 新需求处理

生成的AI上下文须写入必要使用约定，后续不依赖本skill引用：

1. 核对目标与现状差异，定位真实入口/调用链和可复用实现，文档与代码冲突时复核源码后修正事实。
2. 给出建议改法、具体修改位置、接口/字段契约、数据/历史兼容及权限/状态/真实关联统计导出影响和验证范围；简单变更简述，不凑多方案。
3. 仅要求方案时不改代码；明确要求实现时沿已有授权继续。在满足需求、正确性与兼容性前提下，优先复用，以尽可能少的代码改动保持简洁可读，必要联动、验证与同步不能省略。不附带无关重构、格式化、抽象或依赖；确需扩大范围时说明原因，历史候选建议不是新开发指令。
4. 只澄清影响正确性的必要缺口，其余继续；区分方案、完成、失败和未验证，不以文档更新替代实现，不将建议用例写成通过。数据库MCP始终仅查询。

## 双文档同步

1. 先维护AI摘要/需求定位、关键契约和完整事实证据，保留人工决定及未实施建议；真实功能新增/拆分/移除时修复引用，不重排或回收稳定ID。
2. 再由AI事实和当前实现生成五节人版：模块范围、业务流程、Map/枚举与字典、相关统计报表、优化建议。已有九节或其他旧版布局收敛为这五节，不保留字段、页面功能、按钮或代码证据的独立章节/附录。
3. 第2节保留名称主图及地点旁注，按主流程分组用“业务流程、操作地点、业务解析、数据影响、结果与下一步”五列表；步骤名与主图一致，每个地点/具体操作一行，多表在数据影响格按“表名【类型】：说明”用 `<br>` 分条，不按表拆行，不另设业务动作或角色列。
4. 业务解析和数据影响逐行按“本功能＋当前步骤”筛选，仅保留本步必要条件/规则、实际处理及自动联动的数据变化，不能因共用页面/请求/表而混入独立功能。来源CRUD、其他按钮和未执行的后续操作放其所属流程；跨模块回写若由本步实际触发则保留本次影响。必要读取说明用途，通用框架/无关预加载不默认列入。详细依赖/权限、ID和证据在AI按功能归属保存，不因精简丢关键事实；Map/报表/建议约定不变。
5. 实际功能更新在本轮完成AI、人版和索引同步，不等待另一次重新生成请求；只讨论未实施方案时不改写现状，局部核验不升级成全量验证。两份的模块ID、批次、真实基线和范围一致。重新生成若改变目录，先从旧AI取得完整事实再迁移本模块双文档，更新输出记录、文档互链、源码相对链接和索引，不留下两个持续维护的权威位置；仅优化skill不执行迁移。

## 登记模块AI文档索引

首次生成、重新生成或实际功能更新同步两份文档后执行；仅修改skill、局部问答或未实施方案不执行。

1. 两份文档已写入且一致性检查完成后，在目标源码项目的AGENTS.md维护“模块AI文档索引”。用户指定索引文件时使用指定位置；否则使用 `source_root/AGENTS.md`。若该目录仅已有 `agents.md` 则沿用其大小写；两者均不存在时创建 `AGENTS.md`，不在文档预览目录或用户全局规范中另建索引。
2. 复用已有模块索引结构；没有时追加以下三列。按稳定模块ID更新已有条目，首次整理才新增，模块改名或文档迁移时更新对应名称/路径，不重复追加，不改写其他规范、人工说明或其他模块。

   | 模块 ID | 模块名称 | AI 文档 |
   | --- | --- | --- |

3. AI文档链接相对于该AGENTS.md所在目录计算；索引在source_root时，默认链接为 `docs/code-module-feature-map/<项目>/ai-context.md`，其他索引位置或当次路径覆盖按实际位置重算，允许跨仓库相对路径。检查目标存在可读，仅登记实际生成的AI上下文，不登记人版或失败输出。索引附近简短注明：先读对应AI文档并结合当前规范/源码；实际功能修改后先更AI，再同步人版及本索引。
4. 在AI上下文中保留实际索引文件位置及登记约定，便于后续路径变动时同步。索引写入若位于源码仓库，会改变工作区及规范文件指纹；登记后重新核对并同步两份文档的最终基线元数据、相关变更和指纹，不能继续标记工作区干净。索引变更本身不等于业务功能变更，不因此宣称扩大了源码核验范围。
5. 最后复核模块ID、名称和相对链接，重复执行应保持同一条目。交付说明索引实际位置和登记结果；无法写入时保留已生成文档并如实说明索引未完成，不宣称全部完成。

## 同步与交付检查

- 五节人版完整覆盖已核实范围，无改名恢复的字段/按钮/证据章节或附录；不输出重复规则、独立验证报告、集中待确认表或维护流水。
- 主图步骤、地点行及内部ID映射一致，保留所有已确认入口、关键分支、独立状态/结果；步骤/地点变化先更AI关系再同步图与表，不把多请求或多表拆成重复入口行。
- 数据条目对应真实表和本表影响，保留只读/条件/事务/部分成功/未知；相对链接按各自Markdown目录核对，API不充页面，不仅删除绝对前缀。
- 对业务解析和每条数据影响追问“是否属于本功能这一步，是否确实执行或直接决定本步条件/结果”：无关来源CRUD、其他入口规则、后续独立操作及框架背景移出本行；真实自动联动不因跨模块而删除。AI保留必要归属/依赖证据，不能将未发生的后续变更写入本步。
- 首次/重新生成的默认输出归属目标source_root，不在skill工作区或旧预览目录；普通增量维护仍核对登记位置。同一项目/模块目录和模块ID一致，迁移后的文档互链、源码链接和唯一索引条目可解析，不误覆盖其他模块，最终AI记录与真实位置一致。
- 字段/按钮/权限变化仍检查请求、默认、校验、父容器和实际服务门槛；只把影响操作的要点融入人版流程，完整前后端差异及证据保留AI版。已知风险和人工决定不因篇幅精简丢失。
- Map只完整定义一次，实际键值、默认/未命中及端间差异可解释；真实报表三列，不把通用导出当独立报表；建议区分缺陷/业务口径/体验，不误称修复。
- 缺少人版时AI仍能解释现状、找复用/修改位置、形成方案及确定兼容/验证范围；两份事实、基线、范围和内部引用一致，人版表达全面简洁明了。
- 索引只指向正确AI文档，相对链接可读、条目唯一、其他规范保留；登记后的工作区与相关规范指纹同步到最终基线，不能假称干净或扩大核验范围。

交付两份文档与索引的实际位置、覆盖和必要限制，只报告真实完成的检查；维护仅在当前获授权调用中执行，不创建后台监听或定时任务。
