# 需求处理与增量维护

更新已有模块说明，或将生成的 AI 上下文用于后续新需求时读取。后续 AI 只把 AI 上下文作为模块文档输入，开发者说明是同步输出；本流程不授权额外业务开发。

## 核对输入与影响

- 读取当前需求、项目规范、AI 上下文及有关源码，取得基线、覆盖范围、稳定 ID、人工决策和两份输出路径，不要求读取旧开发者说明。
- 比较基线到当前 HEAD，并检查暂存、未暂存和相关新文件；提交号不能覆盖工作区内容，不切换分支、重置或清理用户改动。
- 基线不可解析或事实不足时，从代码及当前用户说明补齐；不回读人版形成依赖，不声称做了精确增量核验。动态角色/字典/配置不可得时就地保留未知。
- 按真实变更扩展到调用方、共享组件及依赖；公共 Map、请求封装、模型和金额计算需检查不同实参/入口的影响。

## 新需求的处理约定

生成时将以下必要约定写入 AI 文档，后续使用不依赖本引用文件：

1. **理解现状差异**：核对需求目标及当前实现，定位入口和调用链，识别已有可复用实现；文档与代码冲突时以复核后的实现修正文档。
2. **提出具体方案**：说明建议改法、关键理由、改动文件/符号、字段或接口契约变化，对历史数据、兼容、权限、状态及实际关联统计/导出的影响，以及验证范围。优先复用现有函数、组件及约定，在完整满足需求、正确性与兼容性的前提下选择代码改动尽可能少、实现简洁可读的方案。简单变更简述，不凑多方案。
3. **按请求执行**：仅要求方案时不改代码；明确要求实现时沿已有授权继续代码修改及适当验证，不机械增加一次批准。修改限于需求直接相关实现，不附带无关重构、批量格式化或不必要的抽象/依赖；必要的调用链联动、校验与文档同步仍须完成，不能以减少行数代替需求完整性。确需扩大改动时简要说明原因。只对影响正确性的必要缺口澄清，其余可独立工作继续。历史候选建议不是新开发指令。
4. **记录真实结果**：区分已完成、未完成、失败、未验证和仍为方案的部分，不以改文档代替完成实现，不将建议用例写成通过。数据库 MCP 仅查询的约束贯穿整个过程。

## 功能更新后的双文档同步

1. 核对实际实现和影响范围，保留未实施建议及重要人工约定。
2. **先更新 AI 文档**：维护前部摘要/需求索引/关键契约，后部完整事实和证据；逐条保留重建业务解析所需的目的、发起前提、步骤关系、关键规则与分支、结果及结束/独立流程边界的依据，同一规则只保留一处完整定义。新增、拆分、移除时修复全部本地引用，不重排稳定 ID。
3. **再更新开发者说明**：从更新后的AI事实和当前代码生成九节人版，无须读取旧人版补背景。第2节依次为2.1主业务流程总览、2.2主业务流程业务解析、2.3起的流程与数据表；主图保留简短业务动作、地点旁注、关键分支和出口，解析紧跟图并按各条主流程分别简述目的、衔接、规则、结果与边界，避免重复地点及数据细节。七列表仍为业务动作、发起角色/来源、操作地点、关键处理、关联数据库/表、生成/变更的数据、结果与下一步；保留完整入口及真实数据影响，具体原则见双文档结构。第3节保留页面四列功能表，第4节合并为七列字段表；第5节不显示证据，第6节不显示按钮ID和证据。完整稳定ID、图节点、角色/操作地点及字段/Map/按钮证据映射集中到第9节。事实不足先补AI文档或标明未知，不能只写一份而宣称同步完成。
4. 两份输出使用一致的模块 ID、真实基线、本次批次及覆盖范围；实际功能更新后在本轮完成同步，不等待另一次重新生成请求。讨论方案未实施时不改写已实现状态，未复核内容不升级为全量已验证。

## 登记模块AI文档索引

首次生成、重新生成或实际功能更新同步两份文档后执行；仅修改skill、局部问答或未实施方案不执行。

1. 两份文档已写入且一致性检查完成后，在目标源码项目的AGENTS.md维护“模块AI文档索引”。用户指定索引文件时使用指定位置；否则使用 `source_root/AGENTS.md`。若该目录仅已有 `agents.md` 则沿用其大小写；两者均不存在时创建 `AGENTS.md`，不在文档预览目录或用户全局规范中另建索引。
2. 复用已有模块索引结构；没有时追加以下三列。按稳定模块ID更新已有条目，首次整理才新增，模块改名或文档迁移时更新对应名称/路径，不重复追加，不改写其他规范、人工说明或其他模块。

   | 模块 ID | 模块名称 | AI 文档 |
   | --- | --- | --- |

3. AI文档链接相对于该AGENTS.md所在目录计算，包含跨仓库相对路径；检查文件存在且可读取。只登记实际生成的AI上下文，不把开发者说明设为后续AI输入，不登记未成功写入的文档。索引附近简短注明：处理对应模块的需求前先读取其AI文档，再结合当前规范和源码核对；实际功能修改后先更新AI文档，再同步开发者说明及本索引。
4. 在AI上下文中保留实际索引文件位置及登记约定，便于后续路径变动时同步。索引写入若位于源码仓库，会改变工作区及规范文件指纹；登记后重新核对并同步两份文档的最终基线元数据、相关变更和指纹，不能继续标记工作区干净。索引变更本身不等于业务功能变更，不因此宣称扩大了源码核验范围。
5. 最后复核模块ID、名称和相对链接，重复执行应保持同一条目。交付说明索引实际位置和登记结果；无法写入时保留已生成文档并如实说明索引未完成，不宣称全部完成。

## 同步检查

- 第2节保持“总览图→集中业务解析→七列表”的顺序，小节从2.3起顺延，整体九节不变。流程目的、步骤衔接、关键规则/分支、结束条件或独立边界变化时，先更AI事实，再同步图、解析和表格；解析仅用已确认事实，不照抄数据表或补造依赖，后续AI仍不读取人版。
- 功能变化检查动作主图、步骤旁的操作地点、必要局部图及字母节点映射、七列业务流程与数据表、第3节四列功能表及第9节映射。新增主流程时补齐其入口、处理路径与出口；页面或触发来源变化更新地点旁注，同类地点可合并列名，不机械增加业务节点。读写表、生成记录、状态或关联关系变化时同步两份文档的逐动作数据说明与代码证据；仅读取不写成生成记录，事务回滚不写成落库成功。改变主要流向、关键分支、关联结果或出口时同步调整主图，独立流程不强行串行。多个F编号可映射同一阶段，但不能合并、重排或丢失功能ID；图简化时同步主图及映射，AI保留完整事实和展示约定。反查关键动作的全部已确认页面调用方；同一动作多入口分行仍复用原F编号，角色未核实如实标注，结果写明下一步或终止。操作地点仅展示页面或真实触发源，接口保留AI文档及证据索引。
- 页面入口链接使用相对路径，注明电脑/手机、菜单/页面、按钮及站点/应用基准，源码按各自Markdown目录计算并校验。输出位置变化时重算链接，不仅删除绝对前缀。第3节条件与第6节一致，简洁表达保留前后端差异。修复引用且不重排稳定ID；AI文档保留完整入口/角色依据、总览与局部图映射、结果及去向，不回读旧人版。
- 字段和 Map 变化检查请求/响应、写入、校验、默认、派生展示及搜索；前后端差异和实际库缺口保留。人版第4节使用合并的七列表，第5节不显示证据；AI文档及第9节保留字段ID和Map证据映射，不能因隐藏列而丢失来源或约束。
- 按钮变化检查父容器、派生标志、实际入参和服务执行条件；人版第6节保持五列，隐藏按钮ID和证据但保留关联功能ID、可用条件及不可用表现。AI文档及第9节保留按钮ID和证据映射，主表与正文不补回隐藏项。
- 报表保持三列及真实入口，保留影响理解的范围；不将通用导出新增为统计报表，不扩展成逐指标财务公式分析。
- 验证场景体现前置状态/输入、操作、页面表现及数据结果；业务期望与实际缺陷分开，未执行不能宣称通过。
- AGENTS.md中的模块索引与当前AI文档一致，链接以索引目录为基准且目标可读；未重复登记，没有新增读取开发者说明的依赖，最终工作区元数据包含本轮索引修改。

## 交付前自检

确认 AI 在没有开发者说明时仍能定位实现、解释规则、形成方案并确定影响/验证；人版可由开发测试直接理解。检查两份事实、基线、范围、ID及链接一致，图表对应有效，人工决策保留。

交付两份文档与模块索引位置、实际登记结果、本次同步范围及限制，不附集中验证报告、待确认表或维护流水。维护在当前调用或获授权的功能更新中执行，不创建后台监听或定时任务。
