# 场景验收

用于优化 skill 或真实试用时验证生成文档是否可用；以下是标准，不是执行结果。不要求每次整理都跑一整套业务测试，也不以格式检查代替实际使用表现。

## 试用方式

选实际模块或隔离样例，提供规范与源码。检查后续 AI 能力时只提供 AI 文档，检查开发测试阅读时单独提供人版。文档生成只读分析；仅求方案不改代码，实际实现遵循当次已有授权与项目约束，数据库 MCP 始终仅查询。

## 典型场景

| 场景 | 请求或输入 | 合格表现 | 主要失败信号 |
| --- | --- | --- | --- |
| 首次整理 | 为选定模块生成双文档 | 人版九节，业务流程五列表含真实操作链接，字母图表对应；第3节按页面及操作顺序用按钮名称/关键规则/触发结果三列表；字段/Map、按钮及三列报表有证据；AI版前置摘要/需求索引，后置独立事实及页面/节点映射 | 两份只换标题，仍按规则类别组织第3节，AI必须回读人版，未知当事实 |
| 页面与操作入口 | 同一功能出现在电脑/手机，含无独立URL的弹窗 | 五列流程表注明各端入口及进入路径，无运行地址时链接真实页面代码；第3节按页面区分按钮、打开及提交，保留成功与拒绝结果；第9节和AI版能追踪稳定ID与图节点 | 编造地址，以写入API充当操作链接，混写两端规则，为ID/证据恢复旧表列，精简表格后丢失功能映射 |
| 新增字段 | 仅为新增一个可选字段提出方案 | 定位输入/显示、请求/校验、服务、模型/存储及实际关联统计/导出；说明复用、默认、可空、历史兼容、修改位置和验证 | 只看表单，无依据要求迁移，不查源码，求方案却改代码 |
| 调整按钮 | 仅为收紧某操作可用条件提出方案 | 核对父容器、隐藏/禁用、派生标志和后端校验，考虑共享入口及直接请求，说明正常与拒绝场景 | 只改visibleOn，把隐藏当服务端已校验 |
| 改变状态 | 仅为增加状态或撤销路径提出方案 | 找到枚举、写入、校验、Map、筛选及实际关联端；考虑时间/财务副作用、旧数据、重复/并发及回归 | 只增Map值，漏状态写入方，把候选流程当现状 |
| 实现与同步 | 明确要求实现某项需求并同步文档 | 在已有授权内实现及适当验证；先更AI事实、再更人版功能与预期，保留ID、人工决策和真实基线 | 无必要重复审批，只改一份，失败却宣称完成 |
| 信息缺失 | 缺实际库、角色绑定或共享源码 | 就地标明缺口及方案依赖，继续可确定部分，仅澄清影响正确性的关键问题 | 猜测DDL/授权，查询其他项目库，或停止全部独立工作 |
| 局部/不适用 | 单字段问答，或未要求全量整理的普通开发任务 | 回答局部或执行原请求，不强制首次建全套报告；已有双文档的功能变更按约定同步 | 关键词命中就全量扫描，擅自实施历史建议 |

## 读者与同步验收

- **AI**：只凭 AI 文档及当前规范/源码，能解释现状、识别复用、给出具体方案、定位修改、判断数据/兼容影响和验证范围；所有 ID 与关键事实可在本文件解析，求方案与求实现边界清楚。
- **开发测试**：通过五列流程表找到主要功能、操作端、功能描述、真实操作链接和处理结果；通过第3节按页面排列的三列功能表找到按钮、关键规则及触发结果。正常、受限及异常检查点有可观察依据，缺陷实际与业务期望不混写，图节点及稳定ID可从第9节追踪。
- **同步**：实际实现变更后，两份事实、ID、基线及覆盖范围一致；候选建议和未验证内容不变成已完成事实。人版技术定位在证据索引，AI文档保留必要技术细节和完整事实。

YAML、链接、ID及格式校验只证明结构有效。交付时只报告真实执行的检查，未试用场景保持未试用；生成的业务文档不另附集中验收结果或维护日志。
