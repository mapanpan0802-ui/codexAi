# 场景验收

用于skill优化或真实试用的合格标准，不是已执行结果；格式校验不等于业务验收，不要求每次整理都运行整套业务测试。仅优化skill不生成业务样例或改模块索引。

## 试用方式

提供目标模块规范与源码，检查后续AI能力时只给AI上下文，检查人版阅读时只给开发者说明。文档生成只读业务实现，仅写双文档和目标项目AGENTS.md模块索引；实际开发遵循当次授权，数据库MCP始终仅查询。

## 典型场景

| 场景 | 请求或输入 | 合格表现 | 主要失败信号 |
| --- | --- | --- | --- |
| 五节首次生成 | 为指定模块整理双文档 | 人版仅模块范围、业务流程、Map/枚举与字典、相关统计报表、优化建议五节；AI独立完整，基线/范围真实 | 仍输出九节，换标题或附录恢复字段/按钮/证据清单，AI须回读人版，未知当事实 |
| 请求目录作为输出基准 | AI请求工作目录与目标源码根/skill目录不同，首次或重新生成 | 文档写入request_root/docs/code-module-feature-map/项目，项目占位按整理对象替换，两文件名不变；source_root仍记录真实源码位置，索引在源码项目 | 错用源码根或skill目录输出，为适配输出改写源码基线，沿用旧预览位置，使用字面占位符或覆盖其他模块 |
| 请求路径固定 | 开始请求后为读代码改变工具workdir或进入其他Git仓库 | request_root取请求环境cwd或明确的AI请求路径并固定；后续切目录不影响输出目标，当次明确输出路径仍可覆盖 | 用最后一次pwd/workdir替换请求起始目录，Git发现导致输出漂移，混淆源码路径与AI请求路径 |
| 路径覆盖与普通维护 | 当次指定其他输出位置，或仅更新已有模块功能 | 当次明确路径优先；普通增量维护沿AI/索引登记位置，不无故搬文档；仅优化skill不生成/迁移样例或改模块索引 | 忽略指定位置，普通小改引发无关目录迁移，或只改skill却搬移业务产物 |
| 旧文档收敛 | 已有九节人版及完整AI事实 | 按五节重组人版，必要规则融入流程，AI保留既有重要技术事实、稳定ID和人工决定 | 为减少人版章节而删除AI字段/按钮/证据，遗漏重要限制或复制整份技术索引到人版 |
| 全面且简洁 | 多入口、多状态、跨模块联动及重复说明 | 覆盖全部已确认入口、关键分支/出口、真实数据关系和重要默认；同一规则完整定义一次，图/流程/Map/报表分工清楚 | 只整理一个页面当全模块，为精简省分支/关联写入，或同义重复和无关细节挤占主线 |
| 主图和步骤对应 | 创建、完成、撤销/取消、独立辅助流程 | 首图用名称串完整主线，地点旁注明确，独立状态不强行串行；五列表首列与主图步骤名一致 | 可见A/B/F编号，页面取代业务动作，缺关键出口或地点归属，靠后续图才能理解主线 |
| 地点行与数据影响 | 多端调用，同一操作连续请求并影响多表 | 按业务流程分组，每个地点/操作一行；五列为业务流程/操作地点/业务解析/数据影响/结果与下一步；逐表按表名【类型】：说明用 `<br>` 分条，条件/只读/失败边界清楚 | 按表重复整行、合并不同按钮或端，原始换行破坏Markdown，表名与变化错配，把部分成功当全部回滚 |
| 本模块与步骤聚焦 | 本模块由外部页面发起，共用请求/服务/表还处理其他模块业务 | 保留发起本模块的入口，解析和数据影响只说明本模块当前步骤；外部依赖及真实联动只保留直接相关部分，不展开外部独立CRUD、按钮及后续操作，AI保留必要依据 | 把同页/同请求所有处理纳入本模块，按目录或表名前缀遗漏真实入口/影响，展开其他模块规则或未执行变更 |
| 流程数据库解析 | 主流程涉及主表、明细表、外部只读来源及逻辑关联 | 主图之后、五列表之前用图示说明本模块相关表的业务作用、步骤读写、关联字段和外键/逻辑关系；与图表及AI事实一致，未知就地说明 | 缺数据库图或顺序错误，只列表名不说明作用/关联，把业务先后当表关系，猜外键/基数，扩成全库结构图 |
| 自动联动与必要读取 | 本步实际自动回写其他模块，也存在无关选择器预加载/框架处理 | 自动回写保留本次实际变更及条件，跨模块不展开全功能；读取仅列直接用于本步校验、查询结果或关联的必要表并说明用途，AI保留完整依赖证据 | 为精简漏掉真实回写，或因为共用表/服务而列无关预加载、登录/配置/审计细节，读取表没有本步用途 |
| 操作规则融入流程 | 存在字段精度、权限、校验及按钮显示/禁用差异 | 关键字段含义/单位、操作前提和可观察结果在流程行简述；完整字段/请求/按钮/权限与证据在AI版 | 新建字段或按钮章节，人版遗漏必要前提，隐藏当服务端校验，或AI跟随删掉技术依据 |
| Map与字典 | 映射用于多个业务表，含字典配置来源、派生值及未知归属 | 人版Map表显示“所属数据表”，以表名.字段名对应实际业务存储，多表同格换行；与字典来源表区分，不落库/待核实明确；键值/文案、默认/未命中及端间差异完整定义一次，AI保存归属证据 | 缺所属表，猜表或线上字典，把配置来源当业务所属表，强行为派生值指定存储表，按表重复键值，或只列枚举类名 |
| 真实报表与建议 | 统计页面、通用导出及有证据的问题并存 | 报表三列只列真实入口及范围；建议简述触发/影响/改进/优先级，区分缺陷与待确认口径 | 把普通列表/导出当报表，编造URL，展开全部公式，把合法独立状态当缺陷或把建议当开发授权 |
| AI独立维护 | 仅AI文档及当前规范/源码 | 能定位代码、解释规则、提出具体方案并判断兼容/验证；保存必要字段、按钮/接口/权限、逐表影响、状态/事务和证据，所有内部ID可解析 | 缺技术事实或只写见人版，盲信旧快照，索引依赖开发者说明 |
| 局部需求与简洁实现 | 新增字段、调整条件或状态的方案/实现请求 | 按真实影响找复用点和调用方，给修改位置/兼容/验证；方案请求不改代码，实现沿授权以尽可能少的改动满足需求并同步 | 只改展示漏后端/关联入口，机械重复审批，顺手重构、格式化或新增不必要依赖，为少改省必要联动 |
| 事实与人工决定同步 | 已完成、候选建议和局部验证并存 | 先更AI事实再更五节人版，保留重要决定、不采纳理由、未完成风险及真实核验边界 | 讨论方案写成已实现，历史待办自动开发，日期更新冒充全量验证，丢既有ID或决定 |
| 索引与迁移 | 从旧位置生成到AI请求目录下，request_root与source_root不同 | 先读旧AI并保留事实/ID/决定，仅迁移本模块双文档；以文档目录重算互链/源码链接，源码AGENTS同一条目用真实跨目录相对路径指向AI文档，其他资料/规范保留 | 因输出在请求目录就改在那里登记索引，直接套用源码根docs链接，留两个维护目标、错链/重复索引/覆盖其他模块，登记失败称完成 |
| 信息缺失与不适用 | 缺库/角色/共享源码，或只是局部问答 | 标明缺口，继续可确定部分，仅澄清影响正确性的必要问题；不强制首次生成全套文档 | 猜DDL/授权，借用其他项目库，停止全部独立工作，关键词命中就全量扫描 |

## 读者与同步验收

- 开发测试能从主流程图、流程数据库解析、五列解析表依次理解业务推进、相关表的作用/关联及每步处理；业务解析/数据影响仅显示与本模块有关的信息，不混写其他模块独立业务。关键Map、真实报表和有依据的建议可查，没有额外技术章节或重复清单。
- AI在没有人版时仍可分析需求、定位实现、完成获授权修改并重建五节人版；人版精简不删除AI必要技术事实，内部ID和代码证据可追踪。
- 两份事实、基线和范围一致，重要差异、风险和未知保留；功能变更同步人版流程与相关Map/报表/建议及模块索引，只报告实际执行的验证，不把标准当结果。
