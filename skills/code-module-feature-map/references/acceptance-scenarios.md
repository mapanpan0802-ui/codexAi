# 场景验收

用于优化 skill 或真实试用时验证生成文档是否可用；以下是标准，不是执行结果。不要求每次整理都跑一整套业务测试，也不以格式检查代替实际使用表现。

## 试用方式

选实际模块或隔离样例，提供规范与源码。检查后续 AI 能力时只提供 AI 文档，检查开发测试阅读时单独提供人版。文档生成只读分析业务实现，允许写双文档及目标项目AGENTS.md模块索引；仅求方案不改代码，实际实现遵循当次已有授权与项目约束，数据库 MCP 始终仅查询。

## 典型场景

| 场景 | 请求或输入 | 合格表现 | 主要失败信号 |
| --- | --- | --- | --- |
| 首次整理 | 为选定模块生成双文档 | 人版九节，第2节以简短业务动作串起完整主流程，操作地点放步骤旁注，主线突出并保留关键分支和出口；图下七列为业务动作/发起角色或来源/操作地点/关键处理/关联数据库或表/生成或变更数据/结果与下一步；第3节页面四列表、字段/Map、按钮及三列报表有证据；AI版保留独立事实及映射 | 页面名称取代业务动作，步骤地点缺失，只画正常主线或要求翻局部图才知关键分支，仍用旧五列表头，漏数据库或数据变化，AI必须回读人版，未知当事实 |
| 主流程入口与简洁性 | 模块有多条独立主流程、同类入口及大量辅助操作 | 主图以“创建任务 → 完成任务”等真实业务动作串联，步骤旁注操作端及页面/触发源；多地点可合并但对应动作可辨识，注释连线与业务/异常流清晰区分；独立流程有自己的入口，辅助动作简短归组，完整事实与映射入表 | 页面或地点注释被当作业务阶段，地点无对应动作，注释连线像必经流程；同类入口展开成大量节点，或为精简删主流程、关键分支、入口及稳定ID |
| 逐步骤数据库与数据 | 同一流程包含创建、完成、查询及条件性联动，多请求可能部分成功 | 七列表逐动作列真实表名及读写用途、生成记录/关键状态/关联键，注明联动条件与事务边界；查询说明仅读取，下载文件不当作入库记录，未核实库名或影响标明未知；AI版保存同一事实及代码证据 | 只列全模块表名不对应步骤，把响应当新增记录、把条件写入当必然、声称失败也全部落库，猜库名/表名或删掉完整证据 |
| 全流程分支与出口 | 模块同时有正常完成、退回重处理、取消终止、关联业务及独立辅助流程 | 第一张总览简洁展示完整业务主线、已核实关键分支及最终结果，独立流程适度分区且不虚构依赖；每项业务动作可定位到总览阶段并与表对应，后续图仅补细节 | 漏取消/退回/失败或等待出口，把所有财务/附件强制排在完成后，用“详见后续图”代替关键分支，有未映射业务动作或虚构连线 |
| 多角色与多创建入口 | 类似“创建理货”的动作存在多个页面调用方，部分具体岗位无法核实 | 表内列全已确认身份与电脑/手机/跨模块操作地点，差异分行且复用功能ID；图中保留创建动作，旁注各真实页面或触发来源，同处理地点可合并；表说明真实读写表、生成记录及创建后状态和下一步，角色未知明确标注 | 把每个页面当作创建步骤，合并地点时丢失来源或漏表内入口；从端或权限码猜岗位，多个入口重编功能ID，结果仅写成功 |
| 页面与操作入口 | 同一功能出现在电脑/手机，含无独立URL的弹窗及跨仓库源码，双文档目录可能不同 | 页面入口注明终端、菜单/页面和按钮；链接使用已确认站内路径或相对于各Markdown目录的真实源码地址并验证；第3节区分打开及提交，保留成功与拒绝结果；第9节和AI版保留完整映射 | 页面入口含机器绝对路径/完整域名，直接去掉前缀造成断链，混淆网页与文件路径，以后端API充当页面入口，精简后丢失映射 |
| 字段与按钮精简 | 生成字段、Map和按钮说明，包含请求响应别名、派生值及多端校验差异 | 人版第4节七列表合并定义与约束，说明请求/响应及来源、可空和编辑限制；第5节无证据，第6节无按钮ID/证据并保留关联功能ID；第9节和AI版保留完整映射 | 仍输出两张字段表，借补充说明塞回ID/证据，删列时丢掉来源/校验，AI版也删除稳定ID与证据 |
| 模块索引登记 | 首次生成后重复生成，AI文档位于项目内或跨仓库目录，可能随后改名/迁移 | 双文档写入校验后，在目标项目AGENTS.md新增或更新同一模块ID条目；相对链接可解析，其他规范/模块保留，索引只引导读取AI文档；最终元数据反映索引修改 | 重复追加、写到全局/预览目录、链接失效、登记失败仍称完成、要求先读开发者说明，或修改AGENTS后仍标记工作区干净 |
| 新增字段 | 仅为新增一个可选字段提出方案 | 定位输入/显示、请求/校验、服务、模型/存储及实际关联统计/导出；说明复用、默认、可空、历史兼容、修改位置和验证 | 只看表单，无依据要求迁移，不查源码，求方案却改代码 |
| 调整按钮 | 仅为收紧某操作可用条件提出方案 | 核对父容器、隐藏/禁用、派生标志和后端校验，考虑共享入口及直接请求，说明正常与拒绝场景 | 只改visibleOn，把隐藏当服务端已校验 |
| 改变状态 | 仅为增加状态或撤销路径提出方案 | 找到枚举、写入、校验、Map、筛选及实际关联端；考虑时间/财务副作用、旧数据、重复/并发及回归 | 只增Map值，漏状态写入方，把候选流程当现状 |
| 实现与同步 | 明确要求实现某项需求并同步文档 | 在已有授权内实现及适当验证；先更AI事实、再更人版功能与预期，保留ID、人工决策和真实基线 | 无必要重复审批，只改一份，失败却宣称完成 |
| 简洁实现 | 明确要求局部功能调整，已有可复用实现 | 在完整满足需求与兼容性的前提下复用现有实现，以尽可能少的代码改动完成；保持可读，完成必要联动、验证和文档同步，确需扩大范围时说明原因 | 顺手重构无关代码、批量格式化、新增不必要抽象/依赖，或为少改而漏掉后端校验、关联入口和必要验证 |
| 信息缺失 | 缺实际库、角色绑定或共享源码 | 就地标明缺口及方案依赖，继续可确定部分，仅澄清影响正确性的关键问题 | 猜测DDL/授权，查询其他项目库，或停止全部独立工作 |
| 局部/不适用 | 单字段问答，或未要求全量整理的普通开发任务 | 回答局部或执行原请求，不强制首次建全套报告；已有双文档的功能变更按约定同步 | 关键词命中就全量扫描，擅自实施历史建议 |

## 读者与同步验收

- **AI**：只凭 AI 文档及当前规范/源码，能解释现状、识别复用、给出具体方案、定位修改、判断数据/兼容影响和验证范围；所有 ID 与关键事实可在本文件解析，求方案与求实现边界清楚。
- **开发测试**：从首图看懂“做什么、在哪里做、下一步是什么”：动作主线完整、地点在对应步骤旁、关键分支与出口清楚，辅助操作简短归组。从图下七列表看懂发起身份、全部已确认操作地点、关键处理、关联数据库/表、生成或变更什么数据、状态与下一步；能回答“哪些身份从哪些页面创建理货，创建了哪些记录，完成时哪些数据变化”。第3节四列表仍说明按钮条件、规则和结果。未知角色、库名及实际缺陷不冒充已确认事实，各功能ID可从第9节定位主图阶段，允许多对一映射。
- **同步**：实际实现变更后，两份事实、ID、基线及覆盖范围一致；候选建议和未验证内容不变成已完成事实。人版第4节为合并七列表、第5节不显示证据、第6节不显示按钮ID和证据；技术定位与隐藏项映射在第9节，AI文档保留完整ID、证据及必要事实。生成校验后AGENTS.md索引指向正确AI文档，无重复条目；仅维护索引，保留原有项目规范和其他模块条目。

YAML、链接、ID及格式校验只证明结构有效。交付时只报告真实执行的检查，未试用场景保持未试用；生成的业务文档不另附集中验收结果或维护日志。
